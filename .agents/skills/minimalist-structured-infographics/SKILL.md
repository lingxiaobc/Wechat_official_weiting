# 极简结构化信息图

将一段文字压缩成一张能够独立传达核心判断的信息图。读者即使跳过正文、只在手机上扫视图片，也应看懂信息的顺序、分组、层级和结论。

若当前环境提供 `imagegen` 技能，先完整阅读并遵循它，再使用位图生成工具。每张不同的信息图单独生成，不把多张图拼成一张画布。

## 默认视觉规格

- 画幅：16:9 横版；优先使用工具原生的最接近 16:9 尺寸。
- 图形：纯二维、扁平化编辑插画和信息图卡片。
- 背景：暖象牙白或浅米白，保留充足留白。
- 主色：低饱和珊瑚红、灰粉、青绿、海军蓝灰；同一语义保持同一颜色。
- 线条：细而清晰，箭头只承担逻辑关系，不作无意义装饰。
- 质感：允许轻微纸张感、柔和色块和少量功能性图标；不使用霓虹、金属、玻璃拟态或强烈光效。
- 风格参考：只借鉴纪念碑谷式的克制配色、干净轮廓和极简图形语言，不借鉴它的空间气质或空间结构。
- 明确禁止：等距建筑、楼梯、平台、透视场景、不可能几何、视觉错觉、悬浮空间、3D 卡片和任何以空间奇观代替信息结构的画面。

小型植物、圆点或线段可用于平衡角落，但只能占很小面积，不能打断箭头、遮挡文字或成为视觉主角。

## 先建立信息模型

生成前，先从上下文中提取：

1. **一个视觉主张**：图片最终要让读者记住的一句话。
2. **一条阅读路径**：从哪里开始，经过哪些节点，在哪里结束。
3. **三层信息**：标题、主要节点、辅助说明与底部结论。
4. **精确文案清单**：逐项列出必须原样渲染的简体中文，不让模型自行补充概念。

不要直接把正文段落塞进图片。把每个节点压缩为“短标题 + 一到两条解释”，保留论证关系而不是保留全部字句。

## 选择结构

根据关系选择最小但足够的结构：

- **两组分界**：用于“理解与能力”“教程阶段与真实能力”等概念边界。左右或上下两组，中间设置明确分界线。
- **分流—汇合流程**：用于一项输入被拆成不同处理路径，最后重新汇合。分支箭头和汇合点必须一眼可见。
- **诊断树**：用于一个结果对应多类原因。上方放问题节点，中部放同层级原因卡，底部放判断标准或行动结论。
- **并列双栏**：用于两类数据、两种方案或两个职责。两栏权重相等，各有定义、项目和一个关键问题。
- **阶段进阶 + 反馈循环**：上层用同高卡片表示从左到右的阶段，下层只连接需要循环迭代的阶段，并画出清楚的返回箭头。

同一层级使用相同尺寸、形状和排版。结构关系由位置、箭头和颜色共同表达，不依赖装饰性空间隐喻。

## 控制信息密度

默认保持本项目现有信息图的中高密度：画面内容充实，但主线可以快速扫描。

- 标题尽量一行，通常为 10–18 个汉字。
- 主要节点通常为 4–7 个；超过 7 个时优先拆成两张图。
- 节点标题通常为 2–8 个汉字；辅助说明尽量控制在一到两行。
- 只保留一个底部结论横条，用一句完整判断收束全图。
- 在约 360 像素宽的手机预览中，标题、主要节点、箭头方向和底部结论必须无需放大即可辨认；次级说明可以更密，但不能承担唯一的关键信息。
- 不要通过缩小所有文字解决内容过多的问题。应删减、归组或拆图。

## 生成提示词骨架

将下列骨架补全后交给图像生成工具。`CONTENT` 部分必须逐字列出中文文案。

```text
Create a polished Chinese infographic for a WeChat Official Account article.

FORMAT: exact 16:9 landscape composition. Flat 2D infographic only.

VISUAL STYLE: minimalist editorial illustration; warm ivory background; muted coral, dusty rose, desaturated teal, and soft navy-gray; generous negative space; clean thin outlines; subtle flat paper-like color fields. Borrow only the restrained palette and minimalist graphic language associated with Monument Valley. Do not imitate its spatial structures.

INFORMATION DESIGN: clearly communicate [顺序 / 分支 / 层级 / 对照 / 循环]. Use [所选结构]. Large, crisp, correctly rendered Simplified Chinese. Every shape and arrow must serve the information structure.

CONTENT, render exactly:
[标题]
[节点、辅助说明、分界标签、结论，逐项列出]

LAYOUT:
[从上到下或从左到右说明各层位置、颜色映射、箭头方向、分支与汇合关系]

NEGATIVE CONSTRAINTS: no isometric architecture, no buildings, no stairs, no impossible geometry, no optical illusion, no 3D perspective, no floating platforms, no English, no watermark, no invented labels. Keep all text large enough for mobile reading.
```

提示词必须同时写清“要画什么”和“绝对不能画什么”。只写“参考纪念碑谷”不足以约束结果，必须重复声明不采用其空间结构。

## 生成与验收

每张图生成后都要查看原图，并依次检查：

1. **文案**：所有中文是否完整、正确，是否出现错字、漏字或模型自创文字。
2. **逻辑**：起点、顺序、分支、汇合、返回箭头和终点是否符合原文。
3. **层级**：标题、主节点、辅助说明、底部结论是否有明显视觉级差。
4. **风格**：是否为二维扁平信息图；是否误用了建筑、楼梯、等距透视或空间错视。
5. **密度**：快速扫视能否抓住主线；细节是否丰富但不挤压主要文字。
6. **一致性**：同组元素的颜色、尺寸和形状是否一致；多张图是否属于同一视觉系统。
7. **上下文**：图中的分类、流程顺序和正文是否一致，不能为了画面整齐而改变含义。

如有关键文案、结构或风格错误，重新生成，不插入错误版本。每张图默认最多尝试两次；仍不合格时说明具体问题并请求用户决定是否继续尝试。保留生成工具的原始文件，把最终采用版本复制到项目目录并使用稳定、带序号的英文文件名。

## 插入文章

只有用户要求插入文章时才修改文章文件。

- 总论图放在核心主张之后，承担阅读地图。
- 流程图放在正文解释完整链路之后，承担视觉总结。
- 诊断图放在提出“错误来自哪里”之后。
- 对照图放在两类对象完成定义之后。
- 阶段与循环图可放在能力总结之后、逐项展开之前。
- 图片应紧邻它所总结的段落，不跨越不相关的小标题。
- 使用能独立说明图片内容的 Markdown alt 文本；确认所有本地路径存在。
- 未经用户授权，不为消除重复而删改正文，只插入图片并报告可能的重复位置。
