# 公众号文章写作与优化

把文章当作读者暂时交付注意力后的回报，而不是单纯的“抓住读者”。优先减少无效认知成本，持续增加理解、判断或行动上的收益。

## 使用资源

- 起草、重构或优化文章前，阅读 [文章架构规则](references/article-architecture.md)。
- 调用子代理进行首次阅读审查前，阅读并严格使用 [首次阅读对抗审查](references/first-reader-review.md)。

## 工作流

按顺序执行。除第 6 步的用户批准外，不为常规写作增加不必要的等待。

### 1. 建立作者输入包

收集并复述以下必需输入：

1. 文章主线：文章最终要证明、解释或带读者看见什么。
2. 作者判断：作者的观点、结论、分歧或方法。
3. 作者感想：经历后的真实感受、困惑、转折或变化。
4. 希望表达：读者读完应带走的理解、行动或情绪。

同时尽量取得目标读者、参考资料、已有标题/草稿、篇幅、语气和发布限制。只有当缺少的信息会阻止界定读者收益或改变作者结论时才提问；否则说明保守假设并继续。

将事实、作者经历、作者判断和待核验主张分开。没有来源时，不把作者感想包装成普遍事实；没有资料范围时，列出需要核验的主张，等待用户授权或提供资料后再补强。

### 2. 形成写作简报

先在内部形成并在输出中简洁呈现：

- 主线与不可改变的作者立场；
- 目标读者及其正在承担的具体痛点；
- 读者收益：读完后多获得的判断、方法、理解或行动；
- 一句话价值承诺：谁能通过本文解决什么，并得到什么；
- 核心结论轮廓与适用边界；
- 文章路线图：每一节为读者新增什么；
- 需要来源支撑或应明确为个人观点的地方。

不要把“作者想说什么”直接当成价值承诺。用“这与读者有什么关系？”审查每个结构项。

### 3. 起草文章

先兑现价值，再逐步建立理解。开头的前两三个短段应直接交代目标读者、痛点、读者收益、核心回答轮廓和必要的适用边界；不要用行业空话、作者自我介绍或悬念代替回答。

正文按以下节奏展开：

`问题或反差 → 本节回答 → 具体场景、经历、资料或证据 → 解释与推理 → 小结/下一问`

让每个主要小节成为一个可独立获得价值的小闭环。抽象观点要落到具体场景，再提炼为可迁移的判断；个人感想要服务于读者理解，而不是占据无关的自我叙述。

按移动端扫描习惯组织：小标题写明本节收益；一段只承担一个意思；关键结论、边界和行动提示易于跳读；长文在前部给出阅读地图。标题、开头和正文必须兑现同一承诺。

### 4. 起草后自检

在调用审查代理前检查：

- 只看标题和开头，读者能否判断“这篇是否为我而写、能带走什么”；
- 每节是否有新的信息增量，而非换说法重复；
- 章节间是否有逻辑桥接，例子是否服务主线；
- 事实、判断和感想是否被诚实地区分；
- 删除后不影响读者收益的铺垫、重复和炫技表达是否已删。

修正显而易见的错字、格式和自相矛盾后，再进入独立审查。

### 5. 进行独立的首次阅读对抗审查

使用至少两名独立子代理；若运行环境确实只允许一名，明确披露降级情况。两名审查者分别模拟：

- 时间有限、以手机扫描文章的普通潜在读者；
- 愿意了解主题、但不熟悉作者背景与隐含前提的普通读者。

每名审查代理只接收标题、副标题或摘要（如有）和完整正文。不得提供作者原始输入、写作简报、提纲、主程序判断、其他审查结果或预设问题。审查代理不得改写文章。使用 `references/first-reader-review.md` 的提示词和报告格式。

保留分歧，不能把不同读者意见平均成一个模糊分数。没有引用到文章位置的意见只可作为低置信观察，不得驱动实质改稿。

向用户展示审查证据时，分别标明每名读者角色、首读决策、关键继续/退出点和文章内定位；再单列共同观察与分歧。可以压缩无关的重复内容，但不得把有冲突的判断合并成模糊结论。

### 6. 输出优化方案并等待批准

主程序汇总审查证据，先输出优化方案，不输出优化后的正文。方案必须包括：

- 保留项：主线、作者判断、感想和已经有效的段落；
- 优先级排序的问题：审查证据、具体位置、为何影响继续阅读；
- 对每项问题的拟议操作：前移、删减、拆分、补桥接、补具体场景、明确边界或重写段落；
- 每项操作预期为读者带来的变化，以及不改变的作者立场；
- 明确的“不会改动”清单。

以 P0（会导致误解或早退）、P1（明显削弱理解/节奏）、P2（可选润色）标记优先级。请用户明确批准全部方案或指定条目后再改稿。用户未批准、仅表示“看看”或只要求解释时，停在方案阶段。

### 7. 获批后修改与复核

只执行用户批准的条目。若修改会改变主线、作者立场、事实主张或目标读者，先给出修订方案并重新等待批准。

交付优化稿和简短变更说明后，重新让隔离的首次阅读审查代理阅读优化稿。报告改善点与仍存在的风险；不要因为复核发现新问题而自动进行下一轮改稿。需要新一轮实质优化时，先提出新的优化方案并等待用户批准。

## 禁止事项

- 不为制造点击而夸大标题、故意隐瞒核心答案或虚构冲突。
- 不把审查代理的推测称为真实读者数据。
- 不让审查代理代替作者决定观点或直接改稿。
- 不在用户批准前执行基于审查结果的实质改写。
